# FDE初回ヒアリングシート — 社内ローカルサーバー

複数スタッフで **同じヒアリング履歴を共有** しながら使うための、ログイン認証つきサーバーです。
ヒアリング内容・見積はサーバーに一元保存され、ログインしたスタッフ全員で共有・継続編集できます。

前バージョンの単一HTML（`../fde_hearing_form.html`）はそのまま画面として使い、サーバー配信時のみ
自動的に「サーバー保存モード」に切り替わります（1つのHTMLで両対応）。

---

## セットアップ

必要環境: **Node.js 18 以上**

```bash
cd server
npm install
npm start
```

初回起動時、**初期管理者アカウント**が自動作成され、ユーザー名とパスワードがコンソールに表示されます。
必ず控えて、初回ログイン後にパスワードを変更してください。

ブラウザで `http://127.0.0.1:8787/` を開く → ログイン画面が出ます。

### 社内LANの他のPCからも使う場合

`server/.env` を作成（`.env.example` をコピー）して:

```
HOST=0.0.0.0
PORT=8787
```

同じLAN内から `http://<サーバーPCのIP>:8787/` でアクセスできます。

---

## スタッフの追加（管理者）

1. 管理者でログイン
2. 右上「管理」→ ユーザー名・初期パスワード・権限を入力して「追加」
3. 本人に初期パスワードを伝える（初回ログイン時に変更を促されます）

「PWリセット」でパスワード再発行、「削除」でアカウント削除ができます。

## セキュリティ設計（実装済み）

| 項目 | 内容 |
|---|---|
| パスワード | **bcrypt**（コスト12）でハッシュ化。平文は保存しません |
| セッション | サーバー側にランダムトークンを保持。クッキーは **HttpOnly / SameSite=Strict**（HTTPS時は Secure） |
| 有効期限 | セッション有効時間（既定12h）＋ **無操作タイムアウト**（既定60分）で自動失効 |
| ログインロック | 連続失敗 **5回で15分ロック**（IP＋ユーザー名単位） |
| CSRF | 変更系リクエストに独自ヘッダ `X-CSRF-Token` を要求し、セッションのトークンと定数時間比較 |
| セキュリティヘッダ | CSP / X-Frame-Options: DENY / X-Content-Type-Options / Referrer-Policy ほか |
| パスワード変更 | 変更・リセット時に本人の他セッションを失効 |
| 監査ログ | ログイン成否・ログアウト・ユーザー操作・削除を記録（`data/db.json`） |
| データ | `server/data/`（パーミッション 0700 / ファイル 0600）に保存。`.gitignore` 済み |

### 本番運用で必ず行うこと

1. **HTTPS 化**（強く推奨）: 逆プロキシ（Nginx / Caddy 等）で TLS を終端し、`.env` に
   `COOKIE_SECURE=1` と `TRUST_PROXY=1` を設定。これで Secure クッキー・HSTS が有効になります。
   - Caddy の例:
     ```
     hearing.example.local {
       reverse_proxy 127.0.0.1:8787
     }
     ```
2. **初期パスワードの変更**（管理者・各スタッフ）。
3. **アクセス範囲の限定**: インターネットに直接公開しない。社内LAN／VPN内に限定するのが安全です。
4. **バックアップ**: `server/data/db.json` を定期バックアップ（全データがここにあります）。
5. OS のディスク暗号化を有効化しておくと、端末盗難時の情報漏洩リスクを下げられます。

### 環境変数（`.env`）

`.env.example` を参照。主な項目:

- `HOST` / `PORT` … 待ち受け（既定 127.0.0.1:8787）
- `ADMIN_USER` / `ADMIN_PASSWORD` … 初期管理者（未指定ならランダム生成）
- `COOKIE_SECURE` / `TRUST_PROXY` … HTTPS 運用時に `1`
- `SESSION_HOURS` / `IDLE_MINUTES` … セッション有効時間・無操作タイムアウト
- `MAX_FAILS` / `LOCK_MINUTES` … ログイン失敗ロック

---

## バックアップ / 移行

- すべてのデータは `server/data/db.json` の1ファイルです。停止中にコピーすればバックアップ完了。
- 各ヒアリングは画面右上「JSONで保存」で個別に書き出すこともできます。

## 注意

- このサーバーは少人数チーム向けの軽量構成（JSONファイル保存）です。数十人規模・大量データになる場合は
  データベース（SQLite/PostgreSQL）への移行を検討してください（`lib/store.js` を差し替える設計です）。
