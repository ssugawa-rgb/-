# OTA掲載変更 指示書システム（デモ）

営業担当がホテルへコンサルティングに伺い、ヒアリングした掲載変更を
「OTA掲載内容 変更指示書」としてまとめ、バックオフィス／運用担当が
その指示書をもとに各OTA（楽天トラベル・じゃらん・Booking.com 等）の
掲載を変更するまでの業務を、Webシステム＋AIで代行するためのデモです。

営業担当が作成された紙の指示書（`OTA掲載内容 変更指示書`）の構成を
そのままシステム化しています。

## できること

- **ログイン認証 / 権限管理**
  - マスター（初期＝あなた）／営業／運用／閲覧 の4権限
  - パスワードは SHA-256＋ソルトでハッシュ化して保存（平文保存なし）
  - ログイン失敗5回で一時ロック
- **指示書の作成・管理**（元PDFの全11セクションに対応）
  - 対象OTA／料金／販売期間／キャンペーン／在庫／掲載開始・停止／OTA個別指示／変更禁止項目／完了チェック／完了報告／具体指示
  - ステータス管理：作成中 → 提出済み → 作業中 → 完了
- **AI連携（Claude API）**
  - ✨ ヒアリングメモ（ドラッグ&ドロップ or 貼り付け）から指示書を**自動記入**
  - ✨ 指示書フィールドから**清書テキスト**を自動生成
- **出力**：印刷／PDF（ブラウザ印刷）、CSVエクスポート

## 使い方

1. `index.html` をブラウザで開く（サーバー不要・単体で動作）。
2. **初回起動**：ログイン画面にマスターID（`s.sugawa@classix.life`）が入っています。
   任意の初期パスワード（6文字以上）を入力して「ログイン」を押すと、その内容でマスター登録されます。
3. ログイン後：
   - 「新規指示書」→ ヒアリングメモを貼り付け →「✨メモから指示書を自動作成」で下書き
   - 各セクションを確認・修正 → 状態を「提出済み」にして保存
   - 運用担当がログインすると、作業完了チェック・完了報告（section 9・10）を記入可能
   - 「印刷/PDF」で先方提出用に出力、「CSV」でデータ出力
4. **AI機能**：右上「API設定」（マスター）で Claude API キーを登録。
   キーはブラウザ内(localStorage)のみに保存され、Anthropic API 以外へは送信されません。
5. **ユーザー追加**：右上「ユーザー管理」（マスター専用）から営業・運用アカウントを発行。

## ⚠️ セキュリティに関する重要な注意（必読）

本システムは **ブラウザ完結型（単一HTMLファイル）のデモ** です。
ログイン・権限制御は「操作体験を見せる」ためのフロントエンド実装であり、
**本番レベルのセキュリティではありません**。具体的には：

- パスワードはハッシュ化していますが、データは各利用者のブラウザ内に保存されるため、
  技術的な知識がある人はブラウザの開発者ツールでデータを閲覧・改変できます。
- 権限制御は画面側での制御であり、サーバー側で強制されていません。
- 端末間でデータは共有されません（各ブラウザにローカル保存）。

→ **先方へのデモ・提案（概念実証）用途** に最適です。実運用で機密データを
複数人で扱う場合は、以下の本番構成への移行を推奨します。

## 本番化の道筋（次ステップ）

- サーバー（バックエンド）＋データベースを用意し、**認証・権限をサーバー側で強制**
- Claude API キーはサーバー側で保持（ブラウザに出さない）
- 監査ログ、承認ワークフロー（営業→運用の受け渡し・差し戻し）
- 各OTA管理画面／API との連携で「掲載変更」まで自動化

## 技術構成

- 単一 HTMLファイル（外部ビルド不要）
- Excel/CSV：SheetJS（CDN）
- AI：Claude API（ブラウザから直接呼び出し・モデル選択可）
- 保存：localStorage（ユーザー・指示書データ）／sessionStorage（ログインセッション）
